**선택: 보스 단위 이력 객체 + Spirit 만 opt-in** (대안: 전 보스 일괄 유지, CombatState 인스턴스 재사용 — 기각).

- 기각 1 — `CombatState` 전체에서 Enter 초기화 제거: WaterMonster(Phase 8)의 쿨다운·`WaterWavePush` 45초 잠금·직전 패턴 감쇠 동작이 바뀌어 Phase 8 계약(D-04a/b, D-06c)과 충돌 위험. 
- 기각 2 — ChaseState/인터셉트 로직을 바꿔 CombatState 재사용: `ChaseStates.cs`, `BossController` 공유 코드 변경 범위가 커서 Phase 5/6 회귀 위험.
- 채택: 추적값을 `PatternHistory` 객체로 분리. 기본(`AcquireHistory`)은 Enter 마다 새 객체 = 현재 동작과 동일(WaterMonster 무변경). `SpiritCombatState` 만 `SpiritController.PatternHistory` 를 돌려줘 상태 인스턴스가 바뀌어도 이력이 이어진다. `Stage2CombatState` 는 `SpiritCombatState` 상속이라 코드 변경 없이 수혜.
- 초기화 지점: `SpiritController.OnStage2Trigger()` 에서 `PatternHistory.Clear()` (Stage 2 는 새 국면 — Clone 연출 직후 첫 패턴이 이전 Exhaustion 체인에 끌려가지 않게). 쿨다운은 `Time.time` 절대 시각이라 별도 만료 처리 불필요.
- 수용된 부작용: 재진입 사이 시간이 길어도(예: 플레이어가 멀리 갔다 돌아옴) 직전이 Exhaustion 이면 복귀 첫 패턴은 WakeRepel 이다. D-04c 의 의도(Exhaustion 직후 반드시 WakeRepel)와 일치하므로 수용.
</design>
