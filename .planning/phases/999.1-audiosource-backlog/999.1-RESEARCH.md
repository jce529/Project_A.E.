## Architecture Patterns

### Recommended file layout (all under existing `Assets/Script/`)
```
Assets/Script/AudioManager.cs    # rewritten IN PLACE (keeps guid 2698f834e59e21a46b7e42ff912b05b5)
Assets/Script/AudioCue.cs        # ScriptableObject + AudioPriority enum
```

New `.cs` files get their `.meta` generated when Unity next imports; they will show as untracked `.meta` pairs afterward (describe in plan; not an error).

### Pattern 1: Bootstrap + coexistence with scene-placed AudioManager
`SaveLoadManager` pattern (verified, `SaveLoadManager.cs:29-49`):
```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
private static void Bootstrap()
{
    if (Instance != null) return;
    new GameObject("AudioManager").AddComponent<AudioManager>();
}
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
private static void ResetStatics() { Instance = null; }   // mirrors AutoSaveTimer
```
Keep the existing `Awake` duplicate-Destroy branch unchanged. Bootstrap runs before any scene object exists, so `Instance` is always the code-created one; the Tutorial Map's scene-placed `AudioManager` (a *child* of GameObject 1579923566, with the stale `bgmSource` field) hits the `else` branch and destroys only its own GameObject. No scene edit needed. (The old `DontDestroyOnLoad` on a non-root GameObject already warned there; that no longer occurs.) Do NOT rename the class or file and do NOT delete/recreate `AudioManager.cs` (its guid is referenced by Tutorial Map and `_Recovery/0`).

**Ordering hazard (verified):** `CurrentSettings` returns `_fallbackSettings` (volumes 1.0) while `SaveLoadManager.Instance` is null (`SaveLoadManager.cs:295-298`), and the relative order of two `BeforeSceneLoad` bootstraps is unspecified. So do NOT only read volumes in `AudioManager.Awake`. Read `SaveLoadManager.CurrentSettings` again in `Start()` (all Awakes done by then) and also at the moment BGM is first played / every voice start (SFX volume is read per play anyway).

- `AudioManager` creates a child GameObject `"BGM"` with `AddComponent<AudioSource>()` then `AddComponent<AudioLowPassFilter>()` (same GameObject). Set `playOnAwake=false`, `loop=true`, `spatialBlend=0`. Set `cutoffFrequency = 22000` initially.
- Default clip: `Resources.Load<AudioClip>("Audio/DefaultBGM")`. To make this load: move `Assets/Music/EA_Checkmate_HIGH_Loop.wav` + its `.meta` together (`git mv` both) to `Assets/Resources/Audio/DefaultBGM.wav`? Renaming changes the file name but the `.meta` guid is preserved; name used by Resources.Load is the file name without extension. Keep the original name instead (`Resources/Audio/EA_Checkmate_HIGH_Loop`) to minimize diff and load by that. The leftover scene AudioSources reference the clip by guid and still resolve. Note: folder `Assets/Resources/Audio/` needs a folder `.meta` (Unity generates).
  - Fallback when the clip is missing: `Debug.LogWarning` once and skip BGM (never throw).
- Optional per-scene override: `AudioManager.PlayBGM(AudioClip clip)` (no-op if same clip already playing) so `EnvironmentManager` could later pass a scene clip; do not add this to `EnvironmentManager` this phase unless planner wants it (YAGNI; all scenes use the same clip).
- Behavior preserved: BGM starts at the first `SetEnvironmentState` call (same trigger as today's `ChangeBGMCutoff` -> `Play()` if not playing). BGM now continues across scene loads instead of restarting per scene (side effect of one persistent source) - see Pitfall 4.

### Pattern 3: Environment state API
```csharp
public enum AudioEnvironmentState { Alive, Neutral, Withered }   // global; NOT named EnvironmentState
[SerializeField] float aliveCutoff = 22000f, neutralCutoff = 5000f, witheredCutoff = 1000f; // AudioManager (code-created, so these are code defaults)
public void SetEnvironmentState(AudioEnvironmentState s)
{
    bgmFilter.cutoffFrequency = s switch { Alive => 22000f, Neutral => 5000f, _ => 1000f };
    if (!bgmSource.isPlaying && bgmSource.clip != null) bgmSource.Play();
}
```
Naming: `EnvironmentManager` has a **private nested** `enum EnvironmentState {None, Alive, Neutral, Withered}`; a global type with the same name would be shadowed inside that class. Use `AudioEnvironmentState` and map in `EnvironmentManager.ApplyEnvironmentEffects` (`case Alive: AudioManager.Instance?.SetEnvironmentState(AudioEnvironmentState.Alive);`). Because a code-created component has no Inspector tuning, hold the three cutoffs as `const`/static readonly (values from the current inspector defaults: 22000/5000/1000). Note existing scene `EnvironmentManager` serialized `aliveCutoff/neutralCutoff/witheredCutoff` values might be overridden per scene - grep verification below shows what is serialized (planner/executor should grep one scene; if any scene deviates from defaults, record it). Removing these public fields from `EnvironmentManager` orphans serialized values only (harmless).
Use `Mathf.Clamp(cutoff, 10f, 22000f)`: Unity clamps cutoff to 10-22000 Hz.
Optional smoothing (current code snaps instantly) - do not add; preserve behavior.

### Pattern 4: SFX API, pool, policies
Public API (recommended minimum; no handle object because only one-shot SFX exist in scope):
```csharp
public bool Play(AudioCue cue);                         // non-positional (2D, spatialBlend 0)
public bool PlayAt(AudioCue cue, Vector3 worldPos);     // positional, fixed point
public bool PlayFollow(AudioCue cue, Transform target); // positional, tracks target
```
Voice record: `{ AudioSource src; AudioCue cue; float startTime; float baseVolume; Transform follow; bool active; }`.

Request flow (all O(16)):
1. `cue == null || clips empty` -> return false (LogWarning once is OK).
2. **Cooldown**: if `Time.unscaledTime - lastPlay[cue] < cue.retriggerCooldown` -> return false. Use `unscaledTime` (pause menu uses timeScale 0).
3. **Concurrency**: count active voices with `voice.cue == cue`; if `>= cue.maxConcurrent` (treat `<= 0` as unlimited) -> reject (return false). Recommended: reject rather than replace-oldest; it is simpler, predictable and matches "limit".
4. **Acquire**: first inactive source; if none, choose the active voice with lowest priority, tie -> smallest `startTime`; if that voice's priority is **higher** than the new cue's priority -> drop the new request; else `Stop()` it and reuse (D-04).
5. Configure: random clip from `cue.clips`, avoid repeating the previous index if length > 1; `volume = cue.volume * SfxVolume`; `pitch = Random.Range(pitchMin, pitchMax)`; `loop=false`; spatial settings; `Play()` (not `PlayOneShot`, so stealing/stop work and per-voice pitch applies).
6. `Update()`: free voices where `!src.isPlaying` (and not paused), update `src.transform.position` for followers.
`SetSFXVolume(v)` stores `SfxVolume` and re-applies `baseVolume * v` to active voices (current code only stores it; live SFX otherwise keep stale volume). `SetBGMVolume` stays `bgmSource.volume = value`. Keep both signatures exactly (used by `SoundSettingsPanel.cs:47,54` via `AudioManager.Instance?.`).

Voice 'active' bookkeeping caveat: `AudioSource.isPlaying` is false right after `Stop()` and when a clip finished, but also false when the source is paused via `AudioListener.pause`. The project does not use `AudioListener.pause` (not verified by grep for it - planner: add a grep step `AudioListener.pause`); if it ever does, voices would be freed early (cosmetic).

### Pattern 5: Positional / tracking playback (2D)
- Pool sources default `spatialBlend = 0`. For `PlayAt/PlayFollow` set `spatialBlend = 1`, `rolloffMode = AudioRolloffMode.Linear`, `minDistance = cue.minDistance`, `maxDistance = cue.maxDistance`, `dopplerLevel = 0`, `spread = 0`. Reset all back for the next non-positional use (voices are reused!) - set every spatial property on every acquire.
- 2D/z-offset hazard: the camera/AudioListener sits at z around -10 while gameplay is at z=0, so a 3D source at z=0 is always >= 10 units away; the cue min/max distances must include that or sounds are inaudible. Recommended: place the source at `new Vector3(pos.x, pos.y, listenerZ)` where `listenerZ = Camera.main != null ? Camera.main.transform.position.z : 0f` so that only XY distance attenuates (MEDIUM confidence: depends on where the AudioListener lives; planner/executor should grep the camera prefab for `AudioListener`. Quick check in this repo: only demo scenes under `Assets/ImportedAsset/*` matched `AudioListener` in `.unity` files; the project's own scenes' listener lives on a Camera component that serialized as `AudioListener` only under demo scenes - i.e. gameplay scenes' listener location is **unverified**; listed as an Open Question).
- Followed target destroyed: Unity's overloaded `==` makes `follow == null` true for destroyed objects. Behavior: on target loss, **stop updating position, let the one-shot finish at the last position** (never stop abruptly: a death sound attached to a dying enemy is the primary use case). Do NOT parent pool sources to targets (destroying the target would destroy the pooled AudioSource).
- Loop SFX: not supported in this phase (no caller needs it; avoids needing a handle/stop API). BGM is the only looping source.

## Common Pitfalls

### Pitfall 1: Corrupting `EnvironmentManager.cs` (CP949)
**What goes wrong:** Edit/Write refuse or corrupt non-UTF-8 bytes (Korean `Header`/comment strings).
**Verified encodings (this run):** `EnvironmentManager.cs` = NOT valid UTF-8 (CP949), CRLF (106 CRLF). `AudioManager.cs` = UTF-8 **without BOM**, contains Korean comments, CRLF (63). `SoundSettingsPanel.cs` = UTF-8 no BOM, Korean, CRLF (70). `SaveLoadManager.cs` = pure ASCII, CRLF (544). New files: write ASCII-only with CRLF (matches siblings, avoids encoding questions).
**How to avoid:** `AudioManager.cs`: full rewrite via Write is fine (UTF-8; keep comments ASCII or Korean UTF-8; Write emits LF - normalize to CRLF afterward or accept; Unity does not care, but git diffs will show whole-file churn anyway because it is a rewrite). `EnvironmentManager.cs`: use a Python byte script (`python -I`) that reads `rb`, operates on `bytes`, and writes `wb`: split on `b"\r\n"`, drop/replace whole lines selected by **ASCII-only anchors** (e.g. lines that contain `bgmSource`, `lowPassFilter`, `ChangeBGMCutoff`, `aliveCutoff`...), insert replacement lines as ASCII bytes with `\r\n`, never `decode`/`str`. Delete whole Korean comment lines by index/anchor, never rewrite their bytes. Verify afterward: `git diff --stat` shows only intended line count, and a byte compare confirms untouched lines identical (e.g. `python -c` hashing unchanged lines), and CRLF count equals expected. Do not use `sed -i` with a locale that may transcode; byte-mode Python is the safe tool.
- Required edits (all anchor-based): delete `public AudioSource bgmSource;`, the Korean comment + `public AudioLowPassFilter lowPassFilter;`, the `[Header("BGM ... (Low Pass)")]` block with 3 cutoff fields and their Korean comments (lines 18-22), the `ChangeBGMCutoff` method (lines 92-106 incl. Korean comments), and replace the three `ChangeBGMCutoff(xCutoff); // Korean` calls (lines 69, 74, 79 - each ends in a Korean comment, so replace the whole line) with `AudioManager.Instance?.SetEnvironmentState(AudioEnvironmentState.X);`. Keep `[Header]` line 5 (Korean) and `waterController`, colors, `backgroundRenderers` intact. Note the blank/`}` structure after deleting a method so braces stay balanced; compile check is only possible in Unity (see Validation).
**Warning signs:** `git diff` shows many changed Korean lines; Unity console shows mojibake in Inspector headers.

### Pitfall 2: Volume ordering (see Pattern 1)
Saved BGM volume lost if applied only in `Awake` before `SaveLoadManager` exists. Re-sync in `Start()`.

### Pitfall 3: Reused pool voices keeping stale spatial settings/pitch
Each `Play*` must set `spatialBlend`, distances, pitch, volume, loop, position every time.

### Pitfall 4: BGM now persists across scenes
Previously each scene had its own BGM source (restarting each scene, silent in MainMenu). With one persistent source, returning to MainMenu (`SaveLoadManager.MainMenuSceneName = "MainMenu"`) leaves BGM playing and the low-pass at the last stage's cutoff. Recommend: subscribe to `SceneManager.sceneLoaded` in `AudioManager`; when `scene.name == SaveLoadManager.MainMenuSceneName` stop BGM and reset cutoff to 22000 (and unsubscribe in `OnDestroy`). This is the only scene-awareness; call it out as a (minor) behavior decision for the planner/user (Open Question 2). Note, each new gameplay scene's `EnvironmentManager` starts with state `None`, so it re-requests its state on load (no stale cutoff in gameplay).

### Pitfall 5: Domain/static state
`Instance` is a static; keep a `SubsystemRegistration` reset (precedent: `AutoSaveTimer.ResetStatics`). Play Mode options are currently with domain reload enabled, so risk is low but costs 3 lines.

### Pitfall 6: Script GUID and `.meta` safety
Never delete/recreate `AudioManager.cs` or its `.meta`. New `.cs` files: Unity generates `.meta` on next focus; two scripts in one file is legal but a MonoBehaviour/ScriptableObject class must match its **file name** (`AudioCue` in `AudioCue.cs`); plain enums may share a file. `AudioCue.cs` MUST be named exactly `AudioCue.cs`.

### Pitfall 7: Creating assets without the Editor
Hand-writing `AudioCue.asset` requires the `MonoScript` guid of `AudioCue.cs`, which does not exist until Unity imports. Therefore **create zero cue assets in this phase's code plan**; list "create example cue(s) via Assets > Create > Audio > Audio Cue" as a manual Editor step (human checkpoint) only if a Play-mode test of SFX is wanted. Without an asset, SFX can be smoke-tested through a throwaway ContextMenu on `AudioManager`?? - no: avoid test-only code (CLAUDE.md simplicity). Prefer the manual editor checkpoint creating one cue and calling from a scratch script the user discards.

### Pitfall 8: `Resources` clip move
Moving the wav: `git mv` both `.wav` and `.wav.meta` (guid stays `e7afddc6...`). Unity is closed during file moves or it must be refocused; do the move as a manual/clearly-scoped step. If the user prefers not to move assets, alternative: AudioManager exposes `[SerializeField] AudioClip defaultBgm` but that needs a prefab -> Resources load of a prefab, which cannot be created without the Editor. Hence the move.

## Code Examples

### Voice acquisition with steal (D-04)
```csharp
int Acquire(AudioPriority incoming)
{
    int lowest = -1;
    for (int i = 0; i < voices.Length; i++)
    {
        if (!voices[i].active) return i;
        if (lowest < 0 || voices[i].priority < voices[lowest].priority ||
            (voices[i].priority == voices[lowest].priority && voices[i].startTime < voices[lowest].startTime))
            lowest = i;
    }
    if (voices[lowest].priority > incoming) return -1;  // never steal a higher-priority voice
    voices[lowest].src.Stop();
    return lowest;
}
```
(Own design; standard pattern. Enum compare works because `AudioPriority` is declared Low < Normal < High.)
