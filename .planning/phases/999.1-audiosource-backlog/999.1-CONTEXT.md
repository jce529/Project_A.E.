# Phase 999.1: 중앙 집중형 오디오 시스템 및 AudioSource 풀링 (BACKLOG) - Context

**Gathered:** 2026-10-26
**Status:** Ready for planning

<domain>
## Phase Boundary

자동 생성되는 영속 `AudioManager`가 BGM/SFX 재생 권한, 데이터 기반 `AudioCue`, 위치·추적 재생, `AudioSource` 풀, 동시 재생 제한·재트리거 쿨다운·우선순위를 중앙에서 소유한다. `EnvironmentManager`는 BGM `AudioSource`나 필터를 직접 조작하지 않고 환경 상태만 판정해 `AudioManager`에 음향 상태 변경을 요청한다. `PersistentManagers` 자동 부트스트랩 구조(BUG-007에서 정리 예정)와 통합한다.

(ROADMAP.md Phase 999.1 의 Goal 을 그대로 범위 앵커로 삼는다. 논의는 HOW 만 다루며 새 기능을 추가하지 않았다.)

</domain>

<decisions>
## Implementation Decisions

### AudioMixer
- **D-01:** 이번 페이즈에서는 `AudioMixer`를 도입하지 않는다. 현재의 `AudioSource.volume` 직접 조절 방식을 유지한다. 볼륨 값은 기존대로 `SaveLoadManager.CurrentSettings`(`setting.json`)의 `BgmVolume`/`SfxVolume`을 읽고, 영구 저장은 설정 패널 저장 흐름이 담당한다(`AudioManager`는 라이브 적용만).
  - 참고: ROADMAP 의 Goal 문구에는 `AudioMixer`가 포함돼 있으나, 사용자가 이번 범위에서 제외하기로 결정했다. 플래너는 Goal 문구와 이 결정이 충돌함을 인지하고 이 결정을 우선한다.

### 환경 음향 요청 방식
- **D-02:** `EnvironmentManager`는 `Alive/Neutral/Withered` 같은 환경 **상태 enum**만 `AudioManager`에 요청한다(예: `AudioManager.SetEnvironmentState(state)`). Low Pass 필터의 cutoff 값과 BGM 재생 여부는 `AudioManager` 내부 매핑이 결정한다. `EnvironmentManager`는 `bgmSource.Play()`와 `lowPassFilter.cutoffFrequency` 직접 대입을 더 이상 하지 않는다. 배경 `SpriteRenderer` 색상 변경은 `EnvironmentManager`에 그대로 둔다.

### SFX 재생 권한
- **D-03:** 모든 SFX 재생을 새 `AudioManager` API(`AudioCue` 기반)로 이관하고, 기존 `PlaySFX(AudioSource, AudioClip)`는 **제거**한다. 호출부 이관 범위를 최소화하려 하지 않고 권한을 완전히 중앙화한다.
  - 현재 C# 코드에는 `PlaySFX` 호출부가 0건이다(Grep 확인). 단, 씬/프리팹에 직렬화된 `UnityEvent` 연결은 Grep 으로 보이지 않으므로 연구·계획 단계에서 씬/프리팹 YAML 도 검색해 확인해야 한다.

### AudioSource 풀
- **D-04:** 풀은 시작 시 **고정 16개**를 생성한다(크기는 Inspector 에서 조정 가능). 풀이 소진되면 **가장 낮은 우선순위, 같으면 가장 오래된** 효과음을 끊고 재사용한다(탈취).

### 동시 재생 제한 / 재트리거 쿨다운
- **D-05:** `maxConcurrent`와 `retriggerCooldown`은 **`AudioCue` 에셋별 값**으로 둔다(전역 기본값만 두는 방식은 채택하지 않음).

### 우선순위
- **D-06:** 우선순위는 3단계 enum(**Low / Normal / High**)이며 `AudioCue`가 하나를 가진다. 숫자 0~255 방식은 채택하지 않는다.

### Claude's Discretion
- BGM `AudioSource`를 누가 소유하는지, BGM 클립을 씬별로 어떻게 지정하는지(현재 `bgmSource`는 Inspector 연결, 자동 생성 `AudioManager`에서는 불가능).
- `PersistentManagers` 부트스트랩과의 구체적 통합 방식(현재 `SaveLoadManager`가 `RuntimeInitializeOnLoadMethod` 부트스트랩을 쓰므로 같은 패턴을 따르는 것이 자연스럽다).
- 위치·추적 재생의 API 형태와 2D 거리 감쇠 처리.
- Alive/Neutral/Withered 별 cutoff 값의 기본 매핑(현재 22000 / 5000 / 1000 Hz).
- `AudioCue` 에셋의 필드 구성 중 위에서 확정하지 않은 항목(클립 배열, 볼륨, 피치 랜덤 범위 등).

</decisions>

## Existing Code Insights

### Reusable Assets
- `AudioManager` 싱글톤 골격: `Instance` + `DontDestroyOnLoad` + `Awake` 중복 제거 로직을 확장 기반으로 재사용 가능.
- `BgmVolume`/`SfxVolume` 프로퍼티와 `LoadVolumes()`: 설정 값 연결부를 그대로 유지.
- `SaveLoadManager`의 `RuntimeInitializeOnLoadMethod` 자동 부트스트랩: 자동 생성 `AudioManager`의 선례.

### Established Patterns
- 이 프로젝트는 State 패턴과 싱글톤 매니저를 쓰며, 설정 영구 저장은 `SaveLoadManager.CurrentSettings` 경유(PlayerPrefs 사용 금지).
- GSD 정책: 개발용 추적 `Debug.Log`는 남기지 않는다(2026-08-20 결정). 진단용 `LogError`/`LogWarning`만 허용.
- CP949 인코딩 `.cs` 파일은 표준 Edit/Write 로 수정하면 비-ASCII 바이트가 훼손된다. 바이트 단위 스크립트가 필요하다(`EnvironmentManager.cs` 해당).

### Integration Points
- `EnvironmentManager.ApplyEnvironmentEffects` → `AudioManager`로의 상태 요청으로 교체.
- `SoundSettingsPanel` → `AudioManager.SetBGMVolume/SetSFXVolume` (시그니처 유지 권장).
- 씬에 배치된 `AudioLowPassFilter`와 `bgmSource` 참조 정리 필요(씬 YAML 수정 가능성).

</code_context>
