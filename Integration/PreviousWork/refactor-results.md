# Project A.E 리팩터링 결과

2026-11-19 · Unity 6000.6.9f1 · 대상 `D:\Projeect_A.E_260521`

기존 런타임 스크립트 22개를 수정하고 Editor 전용 검증 코드 2개를 추가했다. 기존 파일·클래스·공개 콜백 이름과 직렬화 필드 이름을 유지해 씬, 프리팹, Inspector, 애니메이션 이벤트 연결을 보존했다. 공격력, 이동 속도, 공격 패턴 순서, 패턴 선택 비중과 쿨다운 상수는 변경하지 않았다.

## 변경한 구조

| 영역 | 기존 처리 | 변경한 처리 |
|---|---|---|
| 물 자원 | 소비자마다 물병 배열을 반복 순회 | 잔량 캐시와 `TotalWater` 접근자 사용 |
| 물 HUD | 매 프레임 물병 전체 순회 및 슬라이더 갱신 | `OnWaterChanged` 발생 시 갱신 |
| 환경 연출 | 매 프레임 물 잔량과 환경 상태 비교 | 물 변경 이벤트에서 상태 전환 |
| 공격 입력 | PlayerInputHandler의 별도 키 조회 | PlayerAttackBase에서 공통 이벤트 구독·해제, PlayerInputHandler는 호환 부모로 유지 |
| 이동 입력 | 별도 PlayerInput 액션과 고정 달리기 키 | InputHandler가 있으면 같은 이동·점프·달리기 액션 사용 |
| 입력 수명 | OnEnable에서 익명 콜백 추가, 해제 경로 부재 | 이름 있는 콜백을 대칭적으로 구독·해제 |
| 조작 허용 | 대화·일시정지 중에도 개별 입력 경로 동작 가능 | `CanProcessGameplayInput`으로 공통 판단 |
| 웅덩이 풀 | 활성 수 LINQ 순회, 재사용 때 선형 탐색 | 사용 가능 스택과 활성 HashSet으로 조회·반환 |
| 웅덩이 스택 | 별도 카운터와 리스트를 함께 수정 | 리스트 개수를 기준으로 계산하고 중복 등록 방지 |
| 웅덩이 폭발 | Start와 OnEnable에서 중복 구독 가능 | 구독한 이벤트 소스를 추적하고 비활성화 시 정리 |
| 보스 패턴 선택 | 결정할 때마다 List와 전략 객체 생성 | 고정 선택 버퍼와 상태를 보관하지 않는 전략 객체 재사용 |
| 포탈 목적지 | GameManager와 PlayerSpawner가 다른 값을 사용 | 기존 두 공개 API가 같은 목적지를 공유 |
| 키 재설정 | 완료 시에만 작업 정리 | 완료·취소·패널 닫기에 대한 정리 경로 제공 |

물병 사용의 범위 초과, 추가 슬롯 초기화, 정화된 물 회복 시 이전 오염 상태 잔류도 정리했다. 대화와 일시정지가 겹칠 때는 열려 있는 쪽의 정지 상태를 유지하고, 둘 다 닫힌 뒤에는 조작을 재개한다.

## 호환성

- 기존 물 자원 메서드 `AddBottle`, `UseBottle`, `RecoveryWater`, `RecoveryCorruptedWater`, `waterCounter`, `corruptedwaterCounter`를 유지했다.
- 입력 오브젝트가 없는 기존 씬에서는 이전 입력 경로를 계속 사용한다. 공통 InputHandler가 있는 씬은 키 설정을 공유한다.
- 기존 F 기본 공격과 Q 단축키를 유지했다. Input Actions 파일을 다시 연결할 필요가 없다.
- `PlayerAttack`의 애니메이션 이벤트 메서드와 이동 콜백 `OnMove`, `OnJump`를 유지했다.
- 기존 스크립트를 이동·삭제하거나 `.meta` GUID를 재발급하지 않았다.
- 물 데이터의 공개 `bottles` 필드는 호환성을 위해 남겼다. 새 코드는 직접 배열을 수정하는 대신 WaterController의 변경 메서드를 사용해야 잔량 캐시와 UI 이벤트가 함께 갱신된다.

## 검증

Unity 배치 모드로 실제 프로젝트 코드를 컴파일했다. Editor 검증은 빈 플레이 씬에서 실행하며 원래 씬을 저장하지 않는다.

회귀 검증 11개:

1. 물병 추가·소비·정화·오염·범위 초과·변경 알림 및 무작위 조작 500회 후 캐시 일치
2. 물 HUD와 환경의 이벤트 갱신 및 비활성화·재활성화
3. 입력 반복 활성화 시 중복 콜백 방지와 비활성 공격 리스너 해제
4. 공통 입력을 통한 이동과 재지정된 점프·달리기
5. 일시정지·대화의 입력 차단 및 양쪽 종료 순서에 따른 조작 복귀
6. 웅덩이 풀 재사용, 중복 반환, 활성 수와 초기 객체 수 유지
7. 웅덩이 스택 중복 등록·해제·초기화
8. 폭발 이벤트의 단일 구독과 비활성화 시 해제
9. 정령의 공격 순서와 물괴물의 기존 근접 공격 선택지 및 전략 객체 재사용
10. 보스 패턴 선택과 물 잔량 조회의 워밍업 후 관리 메모리 할당
11. 두 포탈 목적지 API의 호환성

할당 측정에서는 **보스 패턴 선택 10,000회: 0바이트**, **물 잔량 조회 100,000회: 0바이트**를 확인했다. 해당 경로의 관리 메모리 측정이며 게임 전체 FPS·GPU 성능 측정은 아니다.

실제 씬 시작 검증:

- `1 stage.unity`: 플레이 모드 120프레임, 이동·점프 입력 포함
- `Tutorial Map.unity`: 플레이 모드 120프레임, 이동·점프 입력 포함

각 씬에서 플레이어 이동·공격·물 자원 컴포넌트 존재 여부와 오류·예외를 확인했다. 전체 보스전 완주, 화면 배치, 체감 밸런스와 렌더링 품질을 보증하는 검증은 아니다.

기존 씬·프리팹·Input Actions·C# 메타파일 231개의 해시와 작업 대상 외 C# 153개의 해시도 비교한다. 상세 실행 결과는 프로젝트의 `Logs/refactor-regression-results.txt`, `Logs/refactor-scene-results.txt`에 저장된다.

## 남아 있는 사항

빌드 설정과 시작 메뉴가 가리키는 `InGame.unity` 파일 부재는 기존 상태 그대로다. 시작 씬을 임의로 바꾸지 않았다. 콤보 피해 배율 전달, 물 도약 강화 수치 반영, 정령 분신 피해와 보스별 장판 규칙 등 기획·밸런스 해석이 필요한 기존 사항은 이번 구조 변경과 분리했다.

코드 원본의 바이트 단위 사본, 적용 해시, 검증 로그는 분석 작업 폴더 `ProjectAnalysis`에 남겼다. 이후 수정이 들어간 파일에 원본을 일괄 덮어쓰는 방식으로 되돌리지 말고 필요한 변경만 선택적으로 비교해야 한다.
